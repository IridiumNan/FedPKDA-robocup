# API 通用约定

> 本文档定义所有后端接口的通用规范，各页面接口文档均遵循本文约定。

---

## 1. 响应结构

- 所有成功响应统一包含 `time` 字段：**服务端时间戳**，格式 `YYYY-MM-DD HH:mm:ss`，用于前端展示数据更新时间。
- 数据字段统一使用 snake_case 命名（如 `packet_loss`、`participation_ratio`）。
- 枚举字段用 `|` 分隔取值（如 `online | warning | offline | unknown`）。

## 2. 鉴权

- 请求头携带：`Authorization: Bearer <token>`
- **协调员** token 可访问：`/overall/*`、`/coordinator/*`
- **运营员** token 可访问：`/overall/*`、`/operator/*`
- 越权访问返回 `403`。
- 角色可见边界的具体含义见 [`../04-role-design.md`](../04-role-design.md)。

## 3. 错误响应

非 2xx 状态码时，响应体统一为：

```json
{
    "time": "str",
    "code": 400,
    "message": "str"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| time | str | 服务端时间戳 |
| code | int | 业务错误码（HTTP 状态码一致） |
| message | str | 错误描述，面向前端展示 |

常用错误码：

| code | 含义 |
| --- | --- |
| 400 | 请求参数不合法（缺字段 / 枚举值错误） |
| 401 | 未认证（token 缺失或过期） |
| 403 | 无权限（角色越权访问） |
| 404 | 资源不存在（如节点 ID 无效） |
| 409 | 状态冲突（如对已处理事件重复处理） |
| 500 | 服务端内部错误 |

## 4. 数据刷新方式

- 列表/统计类接口为**轮询**模式，前端建议每 5–10s 请求一次，服务端不做长连接。
- 写操作（POST）即时返回结果，无需轮询。

## 5. 时间格式

- 时间戳：`YYYY-MM-DD HH:mm:ss`（如 `2026-08-03 15:30:00`）
- 事件发生时间（卡片展示）：`HH:mm`（如 `14:32`）
