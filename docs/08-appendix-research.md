## 一、威胁情报共享机制调研

### ISAC（Information Sharing and Analysis Center）

- **Wikipedia 条目**：<https://en.wikipedia.org/wiki/Information_Sharing_and_Analysis_Center>
- **核心事实**：ISAC 的定义、历史（1998 年 PDD-63 总统令发起）、治理模式。美国有 25+ 个行业 ISAC，各行业成员互为竞争对手但共享威胁情报，成员对自己数据有完全控制权，ISAC 运营方不能强制成员操作。

### FS-ISAC（金融服务 ISAC）

- **官网**：<https://www.fsisac.com/about-us>
- **核心事实**：金融行业最成熟的 ISAC 案例，展示了真实 ISAC 的组织结构、董事会构成、成员间共享粒度分级机制。

### NIST 网络安全框架

- **官网**：<https://www.nist.gov/cyberframework>
- **核心事实**：美国国家标准与技术研究院的网络安全框架，定义了关键基础设施网络安全的治理层级和协作模式参考。

### 已确认的权力分配模型

基于以上来源，提炼出的协作模式：

- **联盟协调方**（类比 ISAC 运营方）：维护平台、发布聚合报告、标记异常。**不能强制成员机构操作**，不能看未共享的原始数据。
- **成员机构**（类比 ISAC 成员）：对自己节点有完全控制权——选择共享粒度、接受/拒绝协调方建议、自主决定参与/退出训练。
- **监管方**（类比政府/法律框架）：提供合规监督和法律保护，不直接访问系统。

## 二、比赛规则要点分析

### 核心考察维度

根据比赛官方评分标准：

| 评分维度 | 分值 | 说明 |
| --- | --- | --- |
| PPT 与答辩表现 | 25 | 演示逻辑清晰度、回答问题能力 |
| 创新性/完整性/可实现性 | 25 | 技术突破和系统实现程度 |
| 专利/软著/论文 | 15 | 已有学术成果支撑 |
| 市场调研和可行性分析 | 10 | 真实需求调研、竞品对比 |
| 具有推广应用价值 | 10 | 投入产出比、商用潜力 |
| 说明书规范 | 10 | 设计思路和分析过程文档 |
| 符合主题要求 | 5 | **偏题则总分乘以 30%** |

### 重要规则

- **开放式命题**，重点考察创新性和技术实现能力
- 作品体现**算法优化或系统开发的独创性**——避免与往届作品雷同
- **技术突破和场景适配度**——明确使用对象和使用场景
- **工程实用性**和**商用潜力**——考虑部署门槛、资源消耗、稳定性
- **规范文档**，可视化交互设计，可复用技术框架
- 视频时长不超过 1 分钟，大小不超过 80 MB，穿插在 PPT 中
- 选拔赛：线上路演 + 专家评审，每队时长（含问答）不超过 8 分钟

### 对设计方向的启示

1. **场景适配度**：选择网络安全垂直场景而非泛化场景，展示对目标用户的理解
2. **竞品对比**：与 legacy 前端的对比分析（见 [07-前端方案对比](./07-frontend-comparison.md)）直接对应此项评分
3. **文档规范**：本文档中心是"说明书规范"评分的直接支撑
4. **可行性分析**：系统基于已发表的 AAAI 论文 + 开源框架，理论可行性已有充分支撑
5. **答辩准备**：核心逻辑链（痛点 → 创新 → 架构 → Demo）应能在 5 分钟内清晰讲述

## 三、系统设计的关键思考框架

> 以下是从系统设计过程中的反思总结，可用于答辩中的方法论展示。

### 信息架构三问

设计每个页面时问自己：

1. **这个页面上的信息，用户需要它做什么决策？**
   - 错误例子："显示 test accuracy 78.3%" → 用户看完然后呢？
   - 正确例子："显示节点行为评分 47/100" → 用户看到后点"隔离"按钮

2. **这个数字的参考系是什么？**
   - 错误例子："偏离度 4.2σ" → 用户不知道 σ 是什么
   - 正确例子："偏离阈值 4.2σ（警戒线 3.0σ），建议隔离" → 用户知道超标了

3. **这个页面的紧急程度是？**
   - 🟢 一切正常 → 不要告警，不要闪烁，安静地显示"正常"
   - 🟡 有可疑 → 显示异常项 + 建议操作按钮
   - 🔴 正在被攻击 → 红色告警 + 自动阻断 + 通知管理员

### 系统设计核心问题

1. 系统用于什么场景？（明确落地价值：部署成本、预期收益）
2. 处理的是什么数据？数据源是什么形式的输入？
3. 如果没有真实数据源，如何做出有说服力的模拟？
4. 数据需要经过多少步核心处理？
5. 系统是自动决策还是辅助决策？
6. 有多少种用户角色？（决定系统需要多少个不同的前端视角）
7. 创新的挖掘点和迭代优化方向？
8. 风险与稳定性评估：算法性能差怎么办？核心成员退出如何保证进度？
