# 系统概述

> 基于 FedPKDA（AAAI 2026）的联邦入侵检测协作平台。
> 面向网络安全联盟场景，让多家机构在不共享原始数据的前提下联合训练检测模型，同时自动隔离恶意节点。

---

## 一、现实痛点

### 1.1 传统联邦学习的三道硬伤

| # | 缺陷 | 后果 |
| --- | --- | --- |
| 1 | **梯度传输**——联邦学习传输梯度而非原始数据 | DLG 攻击可在几轮内像素级还原原始图像（Zhu et al., 2019），共享行为反而扩大了数据暴露面 |
| 2 | **全局 FedAvg 压平个性化需求**——所有客户端共享同一模型 | 数据高度异构的客户端（如银行 vs 电力）被迫使用同质化模型，本地表现退化 |
| 3 | **无法抵抗叛变节点投毒**——假设所有客户端都是"善意的" | 恶意客户端上传虚假参数即可污染全局模型，联盟越大风险越高 |

### 1.2 ISAC 模式的结构性缺陷

ISAC（Information Sharing and Analysis Center）是美国最成熟的行业威胁情报共享机制，但存在结构性缺陷：

- **信任基于"你是谁"**：成员通过法律协议互相信任，协调员作为信息集散中心拥有最高数据访问权限
- **协调员本身是最大安全风险点**：他能看到所有共享数据，一旦被攻陷或被收买，整个联盟的数据暴露
- **共享依赖人工判断**：分析员逐条决定"能不能发"，慢且不一致
- **搭便车无法度量**：没有技术手段检测"只下载模型、不贡献数据"的行为

### 1.3 行业调研数据

- IBM 数据泄露成本报告显示，2024 年全球数据泄露平均成本达 488 万美元
- GDPR 罚款案例表明，隐私合规问题的处罚金额持续上升
- 金融机构、医疗机构、政务系统对跨组织协作的需求迫切，但数据安全顾虑使其止步不前

## 二、目标场景

### 2.1 网络安全联盟

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌──────────┐
│ 省级银行│   │ 政务云  │   │ 电力集团│   │通信运营商│
│ 金融流量│   │ 政务流量│   │ 工控流量│   │ 网络流量 │
└─────┬───┘   └─────┬───┘   └─────┬───┘   └─────┬────┘
      │             │             │             │
      │   ╔══════════════════════════════════╗  │
      │   ║    联盟协调服务器（Coordinator） ║  │
      │   ║    K-Means + 马氏距离 + φ(t)     ║  │
      └───╚══════════════════════════════════╝──┘
```

- **24 家机构**：省级银行（8）、政务云（5）、电力集团（7）、通信运营商（3）、交通（1）
- **数据高度异构**：每家机构的网络流量分布完全不同
- **隐私要求高**：共享入侵检测能力，但不共享原始流量数据
- **存在恶意风险**：联盟内可能有被攻陷的节点在投毒

### 2.2 适用条件

| 适合 | 不适合 |
| --- | --- |
| 数据极度异构（网络安全、个性化推荐） | 数据同质化（CT 影像、标准图像分类） |
| 隐私要求高（金融、医疗、政务） | 客户端算力有限（嵌入式设备） |
| 存在恶意客户端风险（信息具有高价值） | 客户端数量过少（聚类依赖足够样本） |
| 需要跨组织知识共享但互不信任 | — |

## 三、系统定位

### 3.1 一句话描述

> 一个让多家机构在不共享原始数据、不信任彼此的前提下，联合训练入侵检测模型，并自动隔离恶意节点的联邦学习协作平台。

### 3.2 与传统 ISAC 的根本区别

| 维度 | ISAC 模式 | FedPKDA 模式 |
| --- | --- | --- |
| 传输内容 | 原始或脱敏事件数据 | 裁剪+噪声原型（PSNR 6.9，数学不可逆） |
| 协调员能看什么 | 所有共享数据 | 仅聚合统计指标，看不到任何原始数据或原型 |
| 信任基础 | 法律协议 + 身份认证 | 算法保证"你技术上做不了坏事" |
| 异常检测 | 依赖人工举报或主动披露 | 马氏距离自动计算，无需任何一方举报 |
| 贡献度量 | 无法精确量化 | Fisher 信息矩阵天然量化，搭便车自动降权 |
| 共享决策 | 分析员人工判断 | 算法自动加噪上传，无需人工干预 |

### 3.3 核心创新：技术信任替代法律信任

传统 ISAC 共享机制依赖法律协议和控制制度来保护数据安全——**信任基于"你是谁"**。

FedPKDA 通过算法本身剥夺了数据被滥用的可能性——**信任基于"你技术上做不了坏事"**。

关键技术手段：

1. **传输原型而非梯度**：裁剪 + 拉普拉斯噪声，PSNR 6.9 dB，数学上不可逆
2. **马氏距离自动隔离**：异常节点无需人工举报，自动降权
3. **Fisher 量化贡献**：搭便车在数学上无意义
4. **φ(t) 自适应调度**：早期个性化，后期全局泛化，无需人工调参

### 3.4 结果：协调员角色退化

协调员从"必须绝对可信的信息集散中心"变成了一个**轻量的系统管理员**——能看到告警和统计，但技术上拿不到任何可以滥用的数据。

这不是权限控制的改良，而是**架构本身就剥夺了滥用数据的可能性**。即使联盟协调员被攻陷，也拿不到任何可滥用的原始数据。

## 四、实验验证

### Cifar100 基准实验

| 算法 | 模型 | 参数量 | 最佳精度 | vs FedAvg |
| --- | --- | --- | --- | --- |
| FedAvg | CNN | 5.6M | 27.8% | — |
| **FedPKDA** | **CNN** | **5.6M** | **45.1%** | **+17.3pp** |
| FedAvg | ResNet-18 | 11.2M | 24.9% | — |
| **FedPKDA** | **ResNet-18** | **11.2M** | **42.1%** | **+17.2pp** |

*20 客户端, Dirichlet α=0.3, 40 轮*

### 实验结论

- FedPKDA 在 CNN 和 ResNet-18 上均显著优于 FedAvg（+17pp）
- 算法对大模型（ResNet-18）同样有效，具备生产级落地潜力
- 更多实验（UNSW-NB15 网络安全数据集）进行中
