# 角色设计与页面信息架构

> 系统面向两大角色（联盟协调员 + 机构运营员），每个角色拥有完全独立的页面视图和数据边界。
> 合规审计员作为第三角色，暂不设计独立页面。

---

## 一、角色定义

### 角色 1：联盟协调员

- **典型身份**：行业监管机构技术负责人、CERT 联盟联络人
- **使用频率**：周期性巡检（非持续值守）
- **核心诉求**：
  - 联盟是否在正常运转？有没有节点掉线或异常？
  - 全局模型的检测率是否在下降？
  - 哪个节点可能需要关注或通知其负责人？
- **不能做的事**：不能查看任何成员机构的原始数据、不能查看成员上传的原型向量、不能强制操作成员节点

### 角色 2：机构运营员

- **典型身份**：某银行/电力公司 SOC 值班工程师
- **使用频率**：按需查看，出事时深入
- **核心诉求**：
  - 确认本机构数据没有离开自己的服务器
  - 联盟模型对自己机构的检测效果如何
  - 协调员有没有给自己的节点发建议或告警
  - 控制自己节点的参与策略（训练/评估/空闲）
- **不能做的事**：不能查看其他任何机构的信息

### 角色 3：合规审计员（本轮暂不设计页面）

- **典型身份**：第三方审计、监管合规人员
- **核心诉求**：验证隐私协议是否被执行、差分隐私参数是否在承诺范围内、协作过程是否有记录

---

## 二、角色权力边界对比

| | 能看到什么 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| **联盟协调员** | 聚合统计 + 脱敏事件 | 建议隔离、广播通知、调全局参数 | 不能看原始数据、原型、攻击事件 |
| **机构运营员** | 自己的完整信息 | 隔离/恢复节点、调本地参数 | 不能看其他机构任何信息 |

---

## 三、页面结构

### 设计原则

- **直观与易用**：视觉自解释，禁止堆砌专业术语
- **实用性优先**：每一条信息都要能指导行动，每个告警都要有操作入口
- **视觉降噪**：核心信息放在醒目位置，辅助信息渐进式展开
- **明确边界**：聚焦网络安全垂直场景，不泛化

### 页面清单

| 页面 | 解决的用户问题 | 核心用户 |
| --- | --- | --- |
| **事件中心** | "系统发生了什么？要不要广播通知？" | 协调员（主工作台） |
| **节点管理** | "联盟有哪些机构？需要增删或通知特定机构吗？" | 协调员 |
| **节点状态** | "我的节点运行得怎么样？要不要调整参与策略？" | 运营员 |
| **训练控制** | "模型训练到什么程度了？需要调参吗？" | 协调员 + 运营员（不同视图） |
| **安全事件** | "我机构被攻击了吗？怎么追溯？" | 运营员（协调员无权限） |
| **系统架构** | "这个系统怎么运作的？" | 所有角色 |

## 四、各页面信息架构

### 4.1 事件中心（协调员视图）

协调员登录后的主工作台。核心是一个**可操作的事件日志时间线**，每一条都是系统自动检测到的、需要关注的具体事件。

**顶部固定区域（持续监控指标）：**

- 全局检测率：当前值 + 趋势（↑/↓/→）
- 当前训练轮次
- 活跃节点数

**主体区域：事件时间线（按时间倒序）**

```
14:32  ⚠️ 节点 BANK-03 行为偏离 4.2σ（阈值 3.0σ）
      建议：通知该机构自查数据质量或检查是否被攻陷
      [广播通知各机构]  [标记已处理]

13:15  📉 全局检测率连续 5 轮下降（96.3% → 89.1%）
      建议：各节点增加本地训练轮次或检查数据漂移
      [广播通知各机构]  [调整全局参数]

09:47  🆕 系统检测到新型攻击模式（来源匿名）
      已自动纳入全局模型，建议各机构同步
      [广播通知各机构]  [标记已处理]

08:02  🔴 节点 ENG-02 已离线超过 3 轮
      最近响应：07:45
      建议：联系该机构负责人确认状态
      [广播通知各机构]  [标记已处理]
```

**事件类型与算法来源：**

| 事件类型 | 算法来源 | 触发条件 |
| --- | --- | --- |
| 节点行为偏离 | `compute_global_prototypes()` 马氏距离 | 某节点距离 > 3σ |
| 检测率下降 | `rs_test_acc` 趋势分析 | 连续 N 轮下降超过 X% |
| 新攻击模式检出 | 客户端本地推理 | 未知类别检测置信度 > 阈值 |
| 节点离线 | 客户端心跳超时 | N 轮未收到该节点响应 |
| 训练轮次完成 | 服务端训练循环 | 每轮结束自动记录 |

**操作按钮说明：**

- **广播通知**：将该事件（脱敏后）推送给所有成员机构运营员
- **标记已处理**：该事件不再高亮，移入已处理列表
- **调整全局参数**：仅对可参数化应对的事件（如检测率下降时调整训练参数）

### 4.2 节点管理（协调员视图）

协调员管理联盟成员机构的入口。不涉及单个节点的内部运行细节，只关注机构层面的协作关系。

每行一个机构，展示：

- 机构名称 + 行业标识（银行/电力/政务）
- 节点状态圆点（在线/离线/被建议隔离）
- 最近活跃时间
- 行为评分（基于马氏距离，仅显示综合分数，不展示内部细节）
- 该机构负责人联系方式（电话号码，点开展示）

操作：

- **[添加机构]**：邀请新机构加入联盟
- **[移除机构]**：将机构移出联盟
- **[建议隔离]** / **[取消建议]**：标记建议后推送到事件中心并通知该机构运营员

协调员在此页面**不能**看到任何节点的训练数据、本地检测结果、本地原型。

### 4.3 节点状态（运营员视图）

运营员查看和管理**自己机构节点**的完整运行状态。这是运营员看到信息最详细的页面。

展示内容：

- 节点运行状态：在线/离线、当前角色（训练中/评估中/空闲）
- 训练指标：本地训练轮次、本地损失值、本地检测率
- 隐私保护状态：当前噪声注入强度、ε 值、数据传输加密状态
- 模型同步状态：最近一次接收全局模型的时间、本地-全局模型版本号
- 行为评分（自己节点的完整评分，包含偏离度的详细说明）
- 协调员发来的建议/告警（如有）

操作：

- **[隔离]** / **[恢复]**：控制自己节点是否参与本轮全局聚合
- **[配置参与策略]**：切换训练/评估/空闲模式
- **[调整本地参数]**：修改本地噪声强度、local_par、训练轮次等
- **[查看事件详情]**：跳转到安全事件页面查看本机构的相关事件

运营员**只能看到自己机构的信息**，看不到任何其他机构的数据。

### 4.4 训练控制

两个角色进入同一个页面，但看到的信息和可调参数不同。训练是持续运行的，不需要手动开始/停止。

**共同可见区域：**

- 全局检测率趋势折线图（横轴轮次，纵轴检测率，使用已跑完的 experiment_data.json）
- 当前训练轮次 / 总轮次、每轮耗时

**协调员专属：**

- 全局参数面板：
  - `global_par` / `local_par`（影响所有节点的本地-全局对齐平衡）
  - 每轮参与节点比例（`join_ratio`）
  - 异常检测阈值（σ，多敏感算"可疑"）
- 所有节点的贡献度排行（Fisher 权重，含历史趋势）

**运营员专属：**

- 本地检测率 vs 全局检测率对比曲线
- 自己节点的贡献度评分 + 历史趋势
- 本地参数面板：
  - 噪声注入强度（Laplace scale）
  - 本地训练轮次
  - 参与模式切换（训练 / 评估 / 空闲）

### 4.5 安全事件（仅运营员）

**协调员没有此页面权限。** 原因：
- 被攻击是机构的声誉风险——成员机构不希望任何外部方知道自己被攻击过
- 算法本身已经解决了知识传播问题：攻击检测 → 原型更新 → 全局聚合 → 所有成员自动受益
- 协调员在事件中心只能看到一个完全匿名的通知

运营员看到的内容：

- **攻击检测时间线**：攻击类型 + 置信度 + 检测时间 + 影响范围（仅自己机构内）
- **每条的算法来源**：全局模型在本地数据上的推理结果
- **攻击详情展开**：点击某条可查看完整流量特征摘要（不暴露原始载荷）
- **操作**：[标记已处理] / [导出报告]
